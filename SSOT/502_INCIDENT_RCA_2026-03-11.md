## 3. Root Cause Summary

```
RC-1  FastAPI AI 서비스가 Gemini 모델 ID를 `gemini-3-flash`(미지원)로 호출.
      Vertex AI(asia-northeast3)가 404 NOT_FOUND 반환.

RC-2  gemini_client.py에서 404 → LLMServiceError(502, "LLM_SERVICE_ERROR")로 래핑.
      error_handler.py가 HTTP 502 응답 생성.

RC-3  Java BE의 AiProxyService가 FastAPI 502를 수신 → AN001("AI 분석 서비스 연결에 실패했습니다")로
      매핑하여 FE에 전달. → 사용자에게 502 노출.

RC-4  모델명을 gemini-2.5-flash로 롤백해도, asia-northeast3 리전의 Gemini 쿼터 한계로
      429 RESOURCE_EXHAUSTED가 간헐 발생. (과거 재현 확인됨)

RC-5  근본적으로 Gemini API 호출 리전(asia-northeast3)이 쿼터·모델 가용성 모두 제한적.
      us-central1 분리 + 쿼터 상향이 장기 해법.
```

### 현재 활성 vs 잠재 원인 구분

| 구분 | 원인 | 상태 | 발생 조건 |

| 🟠 **구조적** | RC-5: asia-northeast3 리전 한계 | RC-4의 근본 원인 | 리전 분리 전까지 상존 |

## 8. Lessons Learned & Follow-ups

### 8.1 이번 인시던트에서 배운 것

| # | 교훈 | 조치 |
|---|------|------|
| L-1 | **프리뷰 모델을 prod에 바로 적용하면 안 된다.** `gemini-3-flash`는 asia-northeast3에서 아직 미지원이었으나 검증 없이 배포됨. | 모델 변경 시 체크리스트 도입: ① 대상 리전 지원 확인 ② staging 테스트 ③ prod 배포 |
| L-2 | **Gemini 호출 리전과 Cloud Run 리전을 동일하게 두면 쿼터·모델 가용성에 묶인다.** | Gemini API 호출 리전을 config에서 분리 관리 (GEMINI_LOCATION 별도 env var) |
| L-3 | **404 에러가 LLMServiceError(502)로 래핑되어 "연결 실패"로 보이는 것은 정확하지 않다.** 실제로는 "모델 없음"인데 사용자에겐 "연결 실패"로 표시됨. | 404 전용 예외 또는 에러 코드(LLM_MODEL_NOT_FOUND) 추가 검토 |
| L-4 | **DEBUG 로깅을 prod에 남기면 로그 노이즈 + 성능 영향.** | 배포 전 체크리스트에 DEBUG 로깅 제거 항목 추가 |
